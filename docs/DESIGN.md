# Cut Atelier 設計書

作成日: 2026-09-13 / 状態: 初期のレビュー縦一巡を実装済み

決定事項: アプリ名はCut Atelier。画面とサーバー処理はSvelteKit＋TypeScriptで一体化し、adapter-nodeでローカル運用する。DBの利用はユーザー了承済み。初期実装のメタデータ保存にはSQLiteを採用する。動画・画像・音源はファイルで保持し、DBから参照する。

## 1. 目的

映像を見て、気になる場所を指し示し、修正案を比較して採用するループを短くする。人間に視覚情報の詳細な文章化を要求しない。時刻、対象領域、前後関係、素材の版をツールが記録し、エージェントが修正作業に必要な情報へ翻訳する。

主な利用者は演出・採否を判断する人間と、指摘を解釈して画像・動画を制作するエージェント。ローカルPCで動作し、LAN内のブラウザから使用する。「黎明シグナル」の制作は中断したままで、保存済み素材を読み取り専用の検証素材として利用できる。

成功の基準は、指摘を説明する手間、取り違え、修正後の確認時間が減ること。生成モデル自体の品質向上は本ツールの成果と区別する。

## 2. 設計原則

- 指摘は文章だけでなく、フレーム、範囲、矢印、比較対象を第一級の情報として持つ。
- 「変更してほしい」と「ここは維持してほしい」を対等に扱う。
- レイアウト修正は対象を直接操作し、結果を見て調整する体験を目指す。接地や前後の制約入力を毎回要求しない。
- 判断前に前後カットを見られる。単体の美しさだけで採否を決めない。
- 生成成功、エージェントの推奨、人間の採用を区別する。
- 指摘は特定テイクに固定する。新しいテイクへ自動的に移し替えない。
- 採用の変更は履歴に残し、以前の編集状態へ戻せる。
- 人間向け画面にモデル名、seed、ノード番号などを常時表示しない。必要時に制作情報を展開する。

## 4. 基本操作の流れ

1. プロジェクトを開き、現在採用中の編集を音楽とともに再生する。
2. 気になる位置で停止する。必要なら前後へ1フレームずつ移動する。
3. 指摘の時間範囲を設定し、対象を囲む、矢印を描く、短いメモを添える。
4. 維持したい要素も指定し、修正依頼として確定する。
5. エージェントが指摘を読み、必要に応じて画像や短いラフの修正案を返す。
6. 人間が案を選ぶ。エージェントが生成した結果を新しい候補テイクとして取り込む。
7. 元テイクと候補を同じ曲位置で比較し、前後を含めて再生する。
8. 人間が採用すると新しい編集版ができる。該当指摘を解決済みにするかは別に選べる。

「指摘を確定」と「生成を開始」は別操作にする。画面上のメモを書いただけでGPUジョブを投入しない。

## 5. 画面構成

### 5.1 レビュー画面

```text
┌ プロジェクト / 編集版                  保存状態 ┐
│ カット一覧 │ 映像＋描画オーバーレイ │ 指摘一覧 │
│            │ 再生・停止・コマ送り    │ 維持事項 │
│            │ 前後込み再生           │ 修正依頼 │
├ 音楽波形・カット区間・指摘マーカー───────────┤
│ 選択区間 / 指摘を追加 / 新旧比較 / 採用履歴    │
└─────────────────────────────────────────┘
```

PC・横向きタブレットを主対象にする。狭い画面では一覧と指摘パネルを切り替えて表示し、映像を優先する。

曲全体の時刻とカット内時刻を併記する。通常は一つの主映像を使い、前後込み再生は前カット末尾と次カット冒頭を含む区間をループできるようにする。

### 5.2 指摘の作成

必須入力は対象時刻または時間範囲だけ。囲みや矢印だけでも保存でき、長文の説明を必須にしない。

描画は矩形、フリーハンド、矢印を用意する。矢印には「向いてほしい方向」「移動方向」などの任意ラベルを付けられる。解釈できない場合はエージェントが修正案で確認する。

選択肢は「不自然」「向き」「位置・大きさ」「動き」「繋がり」「口元」「その他」程度に抑える。維持指定には「顔」「衣装」「構図」「背景」「動き」と任意の描画を使う。これは修正の要件であり、自動的なピクセル固定を保証する機能ではない。

動画内の領域追跡は初期版では行わない。描画は指定フレームに付く証拠として表示し、必要なら別フレームに描画を追加する。時間範囲全体へ同じ矩形が追従するようには見せない。

### 5.3 新旧比較

左右並列とA/B切り替えを提供する。同じ音楽位置に対応するフレームを表示し、音声は共通マスターだけを一度再生する。各動画の音声を同時に鳴らさない。

比較対象は明示的なテイクIDで固定する。候補が増えても勝手に入れ替えない。尺が異なる候補は曲上の対応区間を指定させ、対応しない部分を「範囲外」と表示する。無断でタイムストレッチして見かけを揃えない。

採用前に候補を仮配置した前後込みプレビューを見られる。停止時の厳密なフレーム比較は、サーバーが抽出した画像で行う。ブラウザのシークだけをフレーム精度の根拠にしない。

### 5.4 修正依頼と履歴

指摘、証拠フレーム、維持事項、前後の接続、エージェントの解釈、提案、結果を一つの依頼にまとめる。「何を直したのか」を結果の横で読めるようにする。

旧テイクへの指摘は旧テイク上に残す。新候補の画面には「この候補で確認する未解決事項」としてリンクを表示する。

### 5.5 空間・スケールの指摘

人物が大きすぎる、マイクが身体に刺さって見える、床と足が接していない、といった問題は単なる囲みと自由文だけでは伝えにくい。対象同士の関係を操作できる「空間の指摘」を設ける。人間が3D座標や焦点距離を入力することは必須にしない。

| 伝えたい内容                 | 画面上の操作                                                 | 保存する意図                                               |
| ---------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| 人物が舞台に対して大きすぎる | 人物と基準物を囲み、足元を基準に希望サイズの枠を縮める       | 画面上の希望サイズ、基準物、固定する接地点                 |
| マイクは人物の手前にあるべき | 二つの対象を選び「こちらが手前」を選択する                   | 対象間の前後関係と適用フレーム                             |
| 足やベースが床から浮く       | 接地点と、接するべき床面を指す                               | 対象の接地要求。床面の確定できない奥行きは未指定           |
| マイクの高さが合わない       | ヘッドと口元を指し、希望する位置へヘッドの目印を動かす       | 基準となる身体部位と位置関係                               |
| カメラの高さや角度が不自然   | 正しく見える参照フレームを選ぶ、または視点違いのラフ案を選ぶ | 希望する見え方。原因の特定はエージェント側で行う           |
| 同じ物の大きさが途中で変わる | 二つの時刻で同じ対象を指定する                               | 同一対象の実寸を維持する要求。投影サイズの固定とは区別する |

元フレーム上に希望する外形を半透明で重ねて表示する。初期版は枠や輪郭による指示で足りるものとし、自動切り抜きやリアルタイム再生成を前提にしない。「理由は分からないが空間が変」という指摘も受け付ける。

画面上で小さくすることと、実物を小さくすることは同義ではない。対象を奥へ移す、カメラを引く、実寸を変える、のどれでも似た見え方になる。初期のドラッグ操作は希望する画面上の結果として保存し、世界座標の変更へ自動変換しない。必要に応じてエージェントが異なる原因に対応するラフを返し、人間が見て選ぶ。

「維持するもの」と組み合わせ、例えば「人物サイズだけ変更、足の接地位置・背景・カメラは維持」と指定できる。互いに実現不可能な要求があれば、黙って一部を無視せず、ラフ案に変更点を表示する。

### 5.6 配置図と視点違いのラフ（次段階）

複雑な指摘には、エージェントが簡易セットの上面図、側面図、撮影カメラからの見え方を並べて返す。人間は人物と小道具の駒を移動し、前後関係、距離、向きを調整できる。形状モデリングやBlenderの操作習得を要求しない。

撮影カメラの設定と対象の実寸を別々に保持する。必要なら人物の身長など、既知の寸法を一つ基準にできるが、未知の値を実測値のように扱わない。斜め撮影の画像上の長さ比を、そのまま物理的な寸法比にしない。

単一の生成画像から一意な3D空間が復元できるとは仮定しない。既存Blenderセットがあればその版を基準にし、なければ「仮配置」として提案する。元画像と配置図の対応が未確認なら明示する。配置図が正しくても生成動画が従う保証はないため、結果の接地・前後・スケールを再レビューする。

### 5.7 目標体験: 触って直すレイアウト

目標は「操作しているうちに、欲しいレイアウトになっている」こと。5.5の関係指定は詳細操作と代替手段に位置づけ、通常は撮影画面上の対象をつかんで調整する。数値入力や3D編集の専門用語を入口にしない。

例えば人物が大きすぎる場合、人物を選び、角を少し縮める。ツールは足元を軸に仮表示を更新し、床との接触を保つ。マイクを動かす場合は、ヘッド・支柱・ベースを一つの物として動かし、ベースを床へ沿わせる。頭だけの位置合わせが必要ならヘッドを選んで高さを変え、支柱が追従する。人間は結果を見て微調整し、いつでも一操作前へ戻せる。

#### 操作と既定の補助

| 操作                           | 既定の動作                                                 | 意図が違った場合                     |
| ------------------------------ | ---------------------------------------------------------- | ------------------------------------ |
| 対象をクリック／タップ         | 対象候補を輪郭で示し、まとまりとして選択                   | 別候補を選ぶ、囲みで指定し直す       |
| 足元・ベースをドラッグ         | 推定または既知の床面に沿って移動し、接地を維持             | 「持ち上げる」操作で高さを変更する   |
| 選択枠の角を縮小・拡大         | 接地点を基準に対象だけの見かけサイズを調整し、カメラを維持 | 「奥へ置く」候補に切り替えて比較する |
| 対象の向きのハンドルを回す     | 接地点を軸に向きを変更し、簡易立体で結果を示す             | 元の向きへ戻す、画像参照で指示する   |
| カメラ操作を選び画面をドラッグ | 被写体の配置を保ち、画角・視点を変更する                   | リセットで操作前のカメラに戻る       |

対象操作中にカメラや無関係な物を勝手に変更しない。背景操作と対象操作は選択状態で区別する。接地、前後関係、部品の一体性は既定の補助として働き、対象選択時だけ小さく表示して解除できる。スナップは弱くし、吸着先を表示する。矛盾がある場合は現在の操作を優先した仮案と影響箇所を示し、毎回確認ダイアログで中断しない。

#### すぐ動く仮表示と、生成による仕上げ

ドラッグ中は切り抜きレイヤーや簡易立体による軽量な表示を更新する。切り抜きが得られない場合は輪郭や箱を使う。隠れていた背景、人物の別角度、影の再描画は後段で処理する。仮表示には「配置ラフ」と明示し、完成映像が修正済みであるようには見せない。

自動選択、床面、接地点、奥行きの推定が外れた場合は、目印を一つ動かす程度で訂正できるようにする。既存Blenderセットがあれば利用し、単一画像からの推定は仮説として保存する。複雑な操作には5.6の配置図を補助として開ける。

操作終了時に結果の配置案を保存する。「この配置で修正」を選ぶと、元画像、配置案、変更した対象、維持する関係を依頼へ変換する。ドラッグごとの高コスト生成は行わない。エージェントが返した修正キーフレームを確認し、動画生成、原速レビューへ進む。

初期版の描画だけではこの体験の完成とは見なさない。次段階の独立した試作で、人物一人・床・マイクに絞り、選択、縮小、接地移動、Undoを説明なしで試せるか評価する。

### 5.8 カット管理

レビューと同じ画面で、曲全体の構成と各カットの制作状態を管理する。サムネイル付きのカット一覧と音楽タイムラインは同じ選択状態を共有し、カットを選ぶと素材、キーフレーム、候補テイク、指摘、修正依頼を表示する。

一覧には表示名、サムネイル、曲上の区間と尺、演出メモ、場所、採用テイク、未解決指摘数、制作状態を表示する。歌詞・曲のセクションは任意に紐づけ、歌詞一行を一カットとする制約は設けない。未生成カットも静止画またはプレースホルダーで配置できる。

| 操作             | 挙動                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| 追加・複製       | カットカードを作り、タイムラインに配置する。複製は新IDを発行し、素材参照を再利用する                   |
| 並べ替え         | 曲上の対象スロットへドラッグする。初期の既定は映像内容の入れ替えで、音楽とスロット境界を保つ           |
| 境界をドラッグ   | 隣接二カットの境界を移し、合計尺を保つ。必要な素材範囲が足りなければ不足表示を出す                     |
| 後続ごと尺を変更 | 明示的にリップル操作を選んだ場合だけ、後続の開始位置を移動する。曲のセクションとのズレをプレビューする |
| 分割             | 再生ヘッドで二つのカットへ分ける。元テイクの入出点を利用できるので再生成は必須ではない                 |
| 統合             | 連続する複数カットの区間を一つの管理単位にする。既存素材の連結を暫定表示できる                         |
| 外す・戻す       | 編集版から取り外す。カットや素材・指摘の履歴は保持し、Undoまたは履歴から戻せる                         |
| 絞り込み         | 未生成、確認待ち、未解決指摘あり、場所、曲のセクション等で一覧を絞る                                   |

短い素材を長いスロットへ置いても、自動で減速・ループ・静止延長しない。「素材不足」として示し、トリム調整、ラフの仮延長、再生成のどれを使うか選べる。仮延長は確認映像に表示する。初期版の編集は単一映像トラックと共通音楽を基本とし、汎用NLEの多層編集を目指さない。

#### 分割・統合と生成の区別

カット統合だけでは一本の生成動画にならない。「統合区間を単一生成する」は別の修正依頼として作る。S08のように旧08dの演技を廃止して全尺を08a〜cの出来事へ再配分する場合は、統合範囲と演出変更を一緒に記録する。

分割や統合で新しいShot IDを発行し、元カットのIDを由来として保持する。表示名には07a・07bなどを使えるが、名前の変更や採番でID、ファイルパス、指摘先を変更しない。既存カットは旧編集版から参照可能なまま残す。

指摘は元テイク上に固定する。新しい分割カットには対応範囲へのリンクを表示し、境界をまたぐ指摘は両方から参照できる。統合単一生成の候補には、元カット群の未解決事項を確認項目として提示し、自動で解決扱いにしない。

#### 制作状態と編集履歴

カットの制作状態は「構成中／素材準備／生成待ち／生成中／確認待ち／採用済み／要修正／保留」を表示する。バックグラウンドのジョブ状態と人間の判断を併記し、失敗ジョブが一件あっても既存の採用テイクを失わない。

並べ替え、尺変更、分割、統合、採用変更はすべてEditRevisionとして記録する。操作中のドラッグは軽量な仮表示、操作終了で一件の編集変更にする。音楽との関係や隣接カットが変わった場合、進行中の修正依頼に「依頼時から構成変更あり」を表示する。元の依頼条件を書き換えたり、実行中の生成を自動で再投入したりしない。

## 6. データモデル

| データ            | 主な内容                                                                                                  |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| Project           | ID、名称、マスター音源ID、出力fps、解像度、状態（進行中／中断）                                           |
| Asset             | ID、メディア種別、保存先、SHA-256、長さ、解像度、fps、作成由来                                            |
| Shot              | 不変ID、表示名（S07等）、演出意図、場所。時間位置は編集版側が持つ                                         |
| ShotLineage       | 分割・統合・複製の種別、元Shot ID群、新Shot ID群、操作時の編集版と対応区間                                |
| Section           | プロジェクト内の曲セクションID、名称、時間範囲。カットとは独立して保持                                    |
| Take              | 不変ID、Shot ID、Asset ID、生成条件資料、基準テイク、作成日時                                             |
| EditRevision      | 不変ID、親編集版ID、作成者、作成日時、変更理由                                                            |
| Placement         | 編集版ID、Shot ID、Take ID、曲上の開始・終了フレーム、素材の入出点、時間変換                              |
| Annotation        | ID、版番号、対象Take ID、作成時の編集版ID、区間、証拠フレーム、描画、メモ、種別                           |
| SpatialTarget     | ID、表示名、対象フレーム上の領域・目印、任意の共通セットObject ID。複数時刻の同一対象の対応は明示的に登録 |
| SpatialConstraint | 指摘ID、対象ID群、前後／接地／希望外形／相対サイズ／実寸維持、基準点、適用時刻、維持事項、指定者          |
| LayoutRevision    | 次段階用。セット版、配置・実寸・カメラ、単位、参照画像、仮配置か確認済みか、前版ID                        |
| LayoutOperation   | 次段階用。対象ID、操作前後の状態、軸・接地点、適用した補助、ユーザー指定と推定の区別。Undoと再現用        |
| RevisionRequest   | 対象指摘の版、基準テイク、前後Placementのスナップショット、維持事項、状態                                 |
| Proposal          | 修正依頼ID、説明、キーフレーム／ラフAsset ID、選択履歴                                                    |
| Job               | 任意の生成連携用ID、実行先ID、状態、開始・終了、エラー、生成条件                                          |
| ReviewDecision    | 対象候補、判断者、採用／保留／不採用、理由、日時                                                          |
| PreviewBuild      | 編集版ID、状態、出力Asset ID、生成設定、エラー                                                            |

生成条件の形式はComfyUIだけに限定せず、ワークフローJSON、プロンプト、使用モデル、seed等を添付できる形にする。Take自体は生成方法を知らなくても再生・比較できる。

Placementは固有IDを持つ。未生成区間ではTake IDを空にでき、静止画参照またはプレースホルダー種別を持つ。統合直後の暫定カットは複数素材の入出点を持つ映像構成Assetを参照し、単一生成候補と区別する。カットカードの制作状態は指摘・依頼・ジョブ・採否から導き、保留などの人間の指定を別記録にする。

### 6.1 時間と描画座標

- 編集時間はプロジェクトfpsを分数で持ち、フレーム番号を整数で保存する。区間は開始を含み終了を含まない。
- 曲上の時刻と素材内の時刻をPlacementで対応づける。秒の小数を足し合わせて編集境界を作らない。
- 音声はサンプルレートとサンプル位置を保存する。元音源の時間軸を維持し、映像末尾との端数の扱いを明示する。
- 可変fps素材は元PTSを保存し、比較用には固定fpsプロキシと対応表を作る。初期版では速度ランプを扱わず、一定倍率の時間変換に限定する。
- 描画は実映像領域の左上を原点とする0〜1の正規化座標。レターボックスの余白を含めない。
- 証拠フレームには素材ハッシュと素材内フレーム／PTSを保存する。編集尺が変わっても指摘の元画像を特定できる。
- 空間指摘では画像座標、配置図の世界座標、物理寸法を別項目にする。画像から確定できない深度や実寸は未設定で保存する。
- 前後関係は視点に依存するため証拠フレームへ結びつける。カメラ移動中も同じ画面上の順序を強制するかは別の要求として扱う。

### 6.2 状態と採用

依頼は「下書き→依頼済み→対応中→確認待ち→完了」を基本とし、保留・取消を持つ。再修正は履歴を残して対応中へ戻す。指摘の変更は版を作り、進行中ジョブに黙って反映しない。

ジョブ成功は確認待ちの候補追加であり、採用ではない。採用操作は新しいEditRevisionを作る。旧版を再び使う場合も履歴を削除せず、新しい編集版として復帰する。

採用APIには画面が参照した編集版IDを渡す。別タブで採用版が更新されていた場合は競合を返し、古い画面から上書きしない。

## 7. システム構成

```text
LANブラウザ
    │ 再生・描画・比較・採用
    ▼
SvelteKit（Node.js） ─ SQLite（指摘・編集版・採否）
    │              └ メディア保管領域（元素材・プロキシ・証拠画像）
    ├ FFmpegワーカー（抽出・プロキシ・プレビュー）
    └ 依頼パッケージ ⇄ エージェント ⇄ 結果パッケージ
                         └ 将来: ComfyUI / Blenderとの連携
```

初期構成は単一ホスト、単一編集者を想定する。メタデータにはSQLiteを採用する。画面とAPIはSvelteKit＋TypeScriptで実装し、adapter-nodeで単一のNode.jsサーバーとして動かす。メディア処理はFFmpegを使う。依存バージョンとSQLiteドライバーは実装開始時に環境確認して決定する。

メディア本体をDBへ格納しない。依頼や採用の書き込みはDBトランザクション、ファイル生成は一時出力後の確定で扱う。中断した変換は再実行できるよう状態を持つ。

プロジェクトごとに一つのDBを置き、バックエンドだけが読み書きする。ブラウザや生成エージェントがDBファイルを直接編集せず、APIまたは取り込み処理を経由する。DBはサーバーのローカルディスクへ置き、LAN越しにDBファイルを共有する構成にしない。

テイク、指摘、編集版の参照は外部キーで整合性を保ち、採用・分割・統合は必要な履歴も含めて一つのトランザクションで確定する。指摘一覧用の対象テイク・状態・時刻、配置一覧用の編集版・開始位置には検索用インデックスを設ける。版番号による競合検知を行い、書き込みロック中の再試行でも採用やジョブ依頼が二重に作られないよう操作IDを保存する。

スキーマ変更は番号付きマイグレーションで管理する。バックアップには整合したDBスナップショットと参照メディアの一覧を含め、復旧時に素材の存在とハッシュを確認する。DB更新とメディア作成は一つの原子的操作にできないため、素材の準備中・利用可能・失敗を記録し、利用可能になってから採用対象へ出す。

映像処理ワーカーは初期設定で直列とし、GPU生成との資源競合を避けるためCPUエンコードを基本候補とする。実測後に調整する。ComfyUIとの依存を切り、停止中でもレビューできる。

### 7.1 保存領域案

```text
src/                            SvelteKitの画面・サーバー処理（新設予定）
workers/                        重い処理の実行コード（新設予定）
data/projects/<project-id>/      ローカルデータ（ソース管理対象外）
  review.sqlite                 指摘と編集履歴
  media/<asset-id>/              固定した素材
  proxies/                      再生用映像
  frames/                       証拠フレーム
  requests/<request-id>/         エージェントへの依頼
  results/<request-id>/          返却された候補
  previews/<edit-revision-id>/   編集版ごとの通し映像
```

DBと原素材・依頼・履歴はバックアップ対象。プロキシや通常の抽出キャッシュは再作成可能だが、指摘の証拠画像は保持する。生成素材やローカル設定をソース管理へ追加しない。

### 7.2 APIの責務案

| 操作                     | 責務                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------- |
| プロジェクト・編集版取得 | 配置、採用テイク、音源、指摘一覧を返す                                             |
| 素材登録・検査           | 種別とハッシュを確認し、プロキシ処理を予約する                                     |
| フレーム取得             | Asset IDと時刻から特定画像を返す                                                   |
| 指摘保存                 | テイクと証拠位置を固定し、更新時は版を確認する                                     |
| 依頼確定・書き出し       | 対象版を固定し、必要資料をパッケージ化する                                         |
| 結果取り込み             | 依頼IDと基準版を照合し、候補を追加する                                             |
| 比較取得                 | 曲上の時刻に対応するA/B素材位置を返す                                              |
| 採用                     | 期待する編集版IDを照合し、新編集版を作る                                           |
| カット編集               | 追加・入れ替え・境界変更・分割・統合を一操作として検証し、新編集版と由来を保存する |
| プレビュー作成           | 指定編集版の映像とマスター音源を合成する                                           |

API経由で任意のシェルコマンドや任意のファイルパスを実行・参照させない。素材は登録されたIDで指定する。

## 8. エージェントへの受け渡し

依頼パッケージは機械可読のJSONと、人間にも読める短い説明、証拠フレーム、描画、前後込みプレビュー、素材参照で構成する。生成条件が既知なら同封する。

必須項目はrequest ID、基準Take IDとハッシュ、指摘の版、曲上の対象区間、素材内位置、前後カット、変更要求、維持事項。大きなモデルや動画を毎回複製せず、同一ホストでは登録済み素材を参照する。

空間修正では、対象ID、接地点、前後関係、希望サイズの重ね表示、比較基準も同封する。世界座標が未確定な要求はそのまま渡し、配置図がある場合だけ対応するセット版と座標を追加する。エージェントは見かけのサイズと実寸・奥行き・カメラのどれを変更する案かを記録する。

エージェントは「解釈」「修正内容」「候補素材」「実施した確認」「残る不確実性」を返す。生成済みファイルを直接採用パスへ上書きしない。結果の基準テイクが現在版と違っていても、旧版への候補として保存し、再適用は人間が判断する。

将来のComfyUI連携では、実行要求に重複防止IDを持たせる。ブラウザ再読み込みで再投入しない。ジョブ取消とファイル削除は別操作とし、他プロジェクトのジョブへ影響する取消方法は使わない。

## 9. 取り込みとプレビュー

既存フォルダから候補を列挙し、プレビューと元パスで選べるようにする。ファイル名の辞書順や更新時刻だけで採用元を決めない。

`SXX_current_final.mp4` のような上書きされるパスは、不変な保管先へコピーまたはcopy-on-writeで固定して登録する。元パスは由来として記録する。ハードリンクは元ファイルの上書きが波及するため固定保存に用いない。

既存マニフェストを取り込めるようにするが、ファイル存在、実尺、フレーム数を実測する。音源や元曲の開始時刻が不明なら「同期未設定」とし、名前から推測した値で同期済みと表示しない。

レビュー用の軽いプロキシと最終画質確認用の原素材を切り替えられるようにする。原速連続再生には編集版単位のプレビューを使用し、採用更新後の生成中は「前の編集版を表示中」と明示する。完成後も再生途中で勝手に差し替えない。

音声は共通マスターを一度配置し、映像側のPlacementから組み立てる。音声のない素材や生成音声付き素材も、この共通時間軸で扱う。

## 10. LAN運用と復旧

既定はローカル待受、LAN公開は設定で有効化する。LAN利用時は接続用トークンで認証し、同一オリジンのUI/APIを使用する。ブラウザからの書き込みは認証とオリジンを検査する。インターネット公開は初期版の対象外。

許可されたプロジェクト領域だけを素材登録対象にする。欠損ファイル、変換失敗、音源未設定、古いプレビューを画面で区別する。変換失敗で採用履歴や指摘を失わない。

下書きは短い間隔で保存し、保存中／保存済み／失敗を表示する。通信失敗時の未送信分はブラウザ側に保持し、再送時に版の競合を検出する。プロジェクトの中断状態では自動生成ジョブを開始しない。

## 11. 段階的な実装と受け入れ条件

### 段階A: 閲覧と指摘

既存の採用映像と音源を取り込み、連続再生、フレーム選択、範囲、描画、維持事項を保存できる。画面サイズを変えても指摘領域が同じ対象を指す。再起動後も同じ証拠フレームを復元できる。

二つの対象の前後指定、接地点、希望サイズの枠と基準点も保存・復元できる。元フレームと希望する外形を重ねて確認し、推測した3D座標を暗黙に保存しない。

カットカードの一覧とタイムラインから対象を選べ、静止画のみの未生成カットも追加できる。各カットの制作状態、候補、未解決指摘へ移動できる。

### 段階B: 依頼と比較・採用

依頼を書き出し、別名で用意した候補を取り込み、A/B比較して採用できる。前後込みプレビューが新しい編集版へ更新される。旧版へ戻せ、旧指摘も失われない。この段階で最初の実用版とする。

カットの入れ替え、境界調整、分割、統合、取り外しと復帰を履歴付きで実行できる。素材不足、未生成区間、意図しない隙間・重複を検出する。未完成区間を含む確認用プレビューは明示付きで作れるが、完成版書き出しでは未解消の不足をエラーとして返す。

### 段階C: 生成連携

修正案の選択後に実行を依頼し、進捗と結果をレビュー画面へ返す。重複実行、旧版への誤採用、プロジェクト中断中の自動再開を防ぐ。

### 次段階の優先試作: 直接操作による配置修正

人物一人、床、一本のマイクを題材に、5.7の軽量な配置操作を試作する。まず手動設定した領域・接地点でもよいので操作感を検証し、その後に自動選択や推定を追加する。高コストの動画生成を接続する前に、接地を保って動くこと、Undoできること、希望する見え方へ到達できることを確認する。

未経験者が数値入力や座標系の説明なしで、人物を小さくする、マイクを手前へ置く、ヘッドを口元へ合わせる、の三課題を実行する。操作数、所要時間、説明を求めた回数、補助機能を訂正した回数を記録する。隠れた自動補正によって意図しない対象まで動いた場合は失敗として扱う。

### 必須検証シナリオ

- S08a〜dを一つへ統合し、総尺を維持したまま、旧08dの演技を含めない単一生成依頼を作れる。
- カット分割後も元テイクの指摘を参照でき、統合・分割をUndoすると元の配置へ戻る。
- 並べ替えの既定動作で音楽と境界が動かず、短い素材の不足が無断の減速で隠されない。
- 生成中のカットを並べ替えても依頼のスナップショットを保持し、結果が別カットへ誤登録されない。

- 「ビルが動く」: 複数時刻の囲みを一件へまとめ、顔を維持指定して依頼する。
- 「急に向きが変わる」: カット境界を前後込みで見て、矢印と隣接テイク情報を渡す。
- 「マイクが不自然」: マイク位置を囲み、ラフ案を比較して修正候補を採用する。
- 「人物が大きすぎる」: 足元を基準に希望外形を縮め、背景とカメラの維持要求を含めて渡せる。
- 「マイクが身体を貫く」: 人物より手前という関係、ベースと床の接点、口元の高さを文章なしでも指定できる。
- 画像上では小さくなるが実寸は同じ、というカメラ移動をスケール破綻と混同しないよう、比較基準と指摘の意味を保存できる。
- 旧テイクの指摘を作った後に別テイクを採用しても、証拠が新テイクへ移動しない。
- 複数タブからの採用が競合した場合、後の操作が無断で上書きしない。
- 可変fps、時間変換、欠損素材、通信断、処理途中の再起動を正しく扱う。
- A/B比較で音声が二重再生されず、停止時に同じ曲時刻を比較できる。

最初の動作確認には保存済み素材を使い、生成ジョブを投入せずレビューの一巡を検証する。ユニット検証は時間変換・座標変換・採用競合、統合検証は取り込み→指摘→依頼→結果→採用→復旧を中心にする。

## 12. 効果の測定と未決事項

測定するのは、問題発見から依頼確定までの時間、指摘の取り違え件数、修正結果の確認時間、採用変更からプレビュー利用までの時間。生成時間は別記録とし、ツールの操作改善と混ぜない。初回試用で現行のチャット・ファイル往復と比較し、目標値を決める。

実装開始時に、主な閲覧端末とLAN帯域、全曲の長さ・素材量、保存領域、元音源の配置を確認する。初期版は複雑な自動領域追跡やブラウザ再生の完全同期を前提にせず、停止時の厳密比較と前後込みプレビューで判断可能にする。

## 13. SvelteKitの実装境界

画面とAPIは同一オリジンで提供し、カット編集・採用などの業務処理をサーバー専用モジュールに集約する。画面操作とエージェント向けAPIから共通の処理を呼び、検証や履歴記録を重複させない。DB接続とファイルアクセスはサーバー側だけに置く。

ドラッグ中の配置と描画はブラウザ内で即時更新し、操作終了時に版番号付きで保存する。動画抽出やプレビュー生成は永続化したジョブから別プロセスで実行し、HTTP処理内で完了を待たない。進捗は初期版ではポーリングで取得できる形にする。ワーカーはアプリと同じリポジトリで管理し、ブラウザとは直接通信しない。

動画配信は登録済みAsset IDから解決し、シークに必要なHTTP Rangeと認証を検証する。メディアをビルド用の静的ファイルへ混在させない。LAN運用時はHOST・PORT・ORIGINを明示する。

公式資料: [ルーティング](https://svelte.dev/docs/kit/routing)、[フォームアクション](https://svelte.dev/docs/kit/form-actions)、[Nodeサーバー](https://svelte.dev/docs/kit/adapter-node)。
